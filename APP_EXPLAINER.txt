================================================================================
  CREDIT RISK SCORING ENGINE — APPLICATION EXPLAINER
================================================================================

WHAT THIS APP DOES
------------------
This is an automated credit risk scoring system. It takes financial and
demographic information about a loan applicant and produces an instant
credit risk score, a risk classification, a lending decision, and an
explanation of which factors drove the outcome.

It is designed for use by loan officers, credit analysts, and risk teams
who need fast, consistent, and explainable credit decisions.

The app has two parts:

  1. A Flask web application with a browser-based UI for submitting
     applications and viewing results.

  2. A REST API for programmatic access — any system can POST applicant
     data and receive a structured JSON score result.

All applications and results are stored in PostgreSQL for audit and history.


--------------------------------------------------------------------------------
HOW IT CALCULATES THE SCORE
--------------------------------------------------------------------------------

STEP 1 — Feature Engineering
  The 14 input fields are reduced to 10 numerical features that the model
  understands. Text fields like employment_type and loan_purpose are excluded
  from the ML model (they are stored for records but not used in scoring).
  The loan_purpose is encoded as an integer (home=0, auto=1, education=2,
  business=3, personal=4, debt_consolidation=5, venture=6).

  The 10 model features are:
    age, annual_income, employment_years, credit_history_length,
    num_credit_accounts, debt_to_income_ratio, loan_amount,
    loan_purpose_encoded, num_delinquencies, payment_history_score

STEP 2 — ML Classification (XGBoost)
  The 10 features are passed into a trained XGBoost gradient boosted tree
  classifier (multi:softprob objective, 160 estimators, max depth 4).

  The model outputs a probability distribution across 3 risk classes:
    Class 0 = LOW risk
    Class 1 = MEDIUM risk
    Class 2 = HIGH risk

  The predicted class is whichever has the highest probability.
  The confidence is that highest probability expressed as a percentage.

STEP 3 — Risk Score Calculation (300–850 scale)
  The risk score is calculated on a FICO-style scale from 300 to 850.

  Base score by predicted class:
    LOW    → 755
    MEDIUM → 635
    HIGH   → 515

  Adjustment formula applied on top of base score:
    adjustment = (payment_history_score − 75) × 1.3
               − debt_to_income_ratio × 95
               − num_delinquencies × 18

  Final score = base_score + adjustment, clamped to [300, 850].

  Score bands:
    300–579  →  Poor
    580–669  →  Fair
    670–739  →  Good
    740–850  →  Excellent

STEP 4 — Decision
  The decision is derived from the risk class and final score:

    APPROVED      →  risk_class == LOW  AND  risk_score >= 690
    REJECTED      →  risk_class == HIGH  OR  risk_score < 580
    MANUAL REVIEW →  everything else (mixed signals)

STEP 5 — Feature Attributions (SHAP)
  The top 5 features that most influenced the decision are identified using
  SHAP (SHapley Additive exPlanations) TreeExplainer.

  Each feature gets an impact value:
    Positive impact → feature pushed the score toward lower risk (good)
    Negative impact → feature pushed the score toward higher risk (bad)

  If the SHAP library is not installed, a heuristic fallback is used instead
  based on the raw feature values relative to typical thresholds.

STEP 6 — Storage
  The applicant data and full score result are stored in PostgreSQL as JSONB
  columns in the applications table, linked to the logged-in user's account.


--------------------------------------------------------------------------------
MODEL TRAINING
--------------------------------------------------------------------------------
The model is trained on a synthetic dataset of 4,000 applicants generated
with realistic statistical distributions (lognormal income, gamma employment
years, beta DTI ratios, Poisson delinquency counts).

A composite financial-pressure signal is computed from the features, and the
top 48% of pressure values are labelled LOW, the next 30% MEDIUM, and the
remaining 22% HIGH. This creates a realistic class imbalance.

The dataset is split 80/20 for training and evaluation. Typical accuracy is
around 90% on the held-out test set.

The model is saved to model.pkl using joblib and loaded once at server startup.
Retrain at any time by running: python train_model.py


--------------------------------------------------------------------------------
INPUT — WHAT THE APP NEEDS
--------------------------------------------------------------------------------
These 14 fields are required to submit a scoring application:

PERSONAL INFORMATION
  name                    Full name of the applicant (text, min 2 characters)
  age                     Age in years (integer, 18–85)
  employment_type         One of: Salaried, Self-Employed, Freelancer, Unemployed

FINANCIAL BACKGROUND
  annual_income           Gross annual income in INR (number > 0)
  employment_years        Years in current or most recent employment (number >= 0)
  credit_history_length   Number of years of credit history (number >= 0)
  num_credit_accounts     Total number of open credit accounts (integer >= 0)
  debt_to_income_ratio    Total monthly debt payments / gross monthly income
                          Expressed as a decimal between 0.0 and 1.0
                          Example: 0.28 means 28% of income goes to debt payments
  existing_loans          Count of currently active loan accounts (integer >= 0)
  num_delinquencies       Count of past payment delinquencies on record (integer >= 0)
  payment_history_score   Composite payment reliability score, 0 to 100
                          Higher is better (100 = perfect payment history)

LOAN DETAILS
  loan_amount             Requested loan amount in INR (number > 0)
  loan_purpose            One of: Personal, Auto, Home, Education, Venture
  tenure                  Requested loan repayment period in months (integer, 6–480)


--------------------------------------------------------------------------------
OUTPUT — WHAT THE APP RETURNS
--------------------------------------------------------------------------------
Every scoring request returns a structured result with the following fields:

  risk_score      Integer from 300 to 850 (higher = lower risk, like a FICO score)

  risk_class      One of: LOW, MEDIUM, HIGH
                  Based on the XGBoost model's predicted probability class

  confidence      Percentage (0–100) representing the model's certainty
                  in the predicted risk class

  decision        One of: APPROVED, REJECTED, MANUAL REVIEW
                  APPROVED      → LOW risk + score >= 690
                  REJECTED      → HIGH risk or score < 580
                  MANUAL REVIEW → all other cases

  top_features    List of the 5 most influential features, each with:
                    feature  — name of the feature
                    impact   — SHAP value (positive reduces risk, negative increases it)

  reasoning       A human-readable sentence explaining the decision

EXAMPLE OUTPUT (JSON)
  {
    "risk_score": 768,
    "risk_class": "LOW",
    "confidence": 94.2,
    "decision": "APPROVED",
    "top_features": [
      { "feature": "annual_income",         "impact":  0.54  },
      { "feature": "credit_history_length", "impact":  0.475 },
      { "feature": "payment_history_score", "impact":  0.25  },
      { "feature": "debt_to_income_ratio",  "impact": -0.16  },
      { "feature": "num_delinquencies",     "impact":  0.0   }
    ],
    "reasoning": "Strong repayment profile and manageable debt burden indicate low probability of default."
  }


--------------------------------------------------------------------------------
API ENDPOINTS
--------------------------------------------------------------------------------
All API routes are under /api/. Authentication uses JWT Bearer tokens.

  POST  /api/auth/register      Register a new user account
  POST  /api/auth/login         Login and receive a JWT token
  GET   /api/auth/me            Get the current user's profile

  POST  /api/applications       Submit an application (scores + stores result)
  GET   /api/applications       List all applications for the current user
  GET   /api/applications/<id>  Get a single application with full result

  POST  /api/score              Score without storing (stateless, no auth required)
  GET   /api/health             Service health check


EXAMPLE API CALL (stateless scoring, no login required)
  curl -X POST http://localhost:5000/api/score \
    -H "Content-Type: application/json" \
    -d '{
      "name": "Jane Smith",
      "age": 34,
      "employment_type": "Salaried",
      "annual_income": 960000,
      "employment_years": 6,
      "credit_history_length": 9,
      "num_credit_accounts": 5,
      "debt_to_income_ratio": 0.28,
      "existing_loans": 1,
      "num_delinquencies": 0,
      "payment_history_score": 88,
      "loan_amount": 280000,
      "loan_purpose": "auto",
      "tenure": 48
    }'
